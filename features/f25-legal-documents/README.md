# F25 — Legal documents publication gate

This slice publishes Postqron's Terms, Privacy Policy, Cookie Policy, DPA and
subprocessor registry through a fail-closed release gate: nothing is ever
served that has not passed `auditLegalRelease` as a complete, approved,
digest-verified release.

## Current state

Release `0.1` for market `IT` is live, following the external legal approval
recorded under reference `LEGAL-APPROVAL-2026-07-25-F25`
(https://github.com/apdsoftware/postqron/issues/134#issuecomment-5080412206):

- `/legal/terms`, `/legal/privacy`, `/legal/cookies`, `/legal/dpa`, and
  `/legal/subprocessors` return HTTP 200 in `en`, `it`, `es`, `fr`, and `de`;
- the versioned API adapter (`/api/v1/legal-documents/...`, including the
  legacy `terms_it`/`privacy_it`/`cookies_it`/`dpa_it` aliases) serves the
  approved artifact with its exact digest, version, and approval metadata;
- `src/bundle.ts` is a generated, static artifact — see "Regenerating the
  bundle" below — committed ahead of time so the browser bundle never pulls
  in Node's `fs`/`path`/`url` built-ins;
- any release that is incomplete, unapproved, digest-mismatched, or missing
  required evidence remains fail-closed: `auditLegalRelease` rejects it and
  the API/page fall back to `legal_release_blocked` (HTTP 503,
  `Cache-Control: no-store`), never partial or draft content. See
  `test/release-gate.test.ts` for the fail-closed coverage against an empty
  input, and `test/api.test.ts` / `test/api-matrix.test.ts` for the same
  guarantee at the HTTP layer.

The page routes are declared in `feature.yaml` so the runtime can compose them
without editing a central route registry. The API-neutral handler in
`src/api.ts` defines the behavior expected below `/api/v1/legal-documents`.

## Regenerating the bundle

`src/bundle.ts` is generated by `scripts/build-bundle.ts` from:

- the approved corpus in `content/drafts/**` (front matter `status: approved`,
  one file per document × locale);
- the verified provider evidence in `content/subprocessors.json`.

Digests are computed mechanically from the corpus (SHA-256 over each
artifact's body). Regenerate after any change to the approved corpus:

```sh
node --experimental-strip-types features/f25-legal-documents/scripts/build-bundle.ts
```

Do not hand-edit `src/bundle.ts`; change the source corpus or the generation
script instead. A new legal release (a new version, a new market, or updated
content) requires its own recorded external approval reference before the
script is updated to include it — the script and the gate do not accept an
unapproved artifact regardless of how the bundle is generated.

## Release controls

`auditLegalRelease` rejects the entire bundle unless:

- all 25 current document/locale combinations are referenced by each release;
- every referenced artifact exists and its SHA-256 digest matches its exact
  content bytes;
- each artifact has complete immutable version, controller, contact,
  approval, publication, effective-date, and change-history metadata;
- no drafting markers are present in content or metadata;
- all required legal/provider evidence records are present and verified;
- the release uses market `IT`, English fallback, and a complete independent
  legal release approval;
- release versions and effective dates increase monotonically.

Previously effective releases remain addressable by version after a newer
release becomes current. Unsupported or unavailable locales explicitly fall
back to English and report that fallback in the response.

## API

The framework-neutral adapter supports:

```text
GET /api/v1/legal-documents/{terms|privacy|cookies|dpa|subprocessors}/current?locale=it
GET /api/v1/legal-documents/{terms|privacy|cookies|dpa|subprocessors}/versions/{major.minor}?locale=it
```

The legacy keys `terms_it`, `privacy_it`, `cookies_it`, and `dpa_it` are
accepted at the adapter boundary for compatibility with the current
marketing-site proxy. Only GET is allowed. Approved responses include the
exact digest, version, locale, approval metadata, permanent URL, and content.
Blocked responses never include legal content.

## Verification

From the repository root:

```sh
node --experimental-strip-types --test features/f25-legal-documents/test/*.test.ts
pnpm exec tsc --noEmit -p features/f25-legal-documents/tsconfig.json
pnpm exec eslint features/f25-legal-documents
pnpm test:runtime-bundle
pnpm --filter @postqron/web build
```

The tests use synthetic fixtures that are never loaded by the production
bundle and do not represent legal approval.
